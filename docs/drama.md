# Short drama mode (fal.ai)

Turn a one-line premise into a photoreal short drama: consistent characters,
lip-synced spoken dialogue, ambient sound, assembled into one MP4.

This is different from the normal MoneyPrinterTurbo flow (narration over stock
footage). Each shot is generated by an AI video model, so **rendering costs
money on your fal.ai account**. Planning is free.

## How it works

| Step | What happens | Cost |
|---|---|---|
| `plan` | Your configured LLM (Ollama, OpenAI, ...) writes `screenplay.json`: characters with a fixed look and voice, and 8-second shots with action, camera and dialogue. | Free with Ollama |
| `estimate` | Shows what is still missing and what it will cost. | Free |
| `render` | 1. One photoreal reference portrait per character (Nano Banana Pro). 2. One 8-second shot per screenplay shot with **Veo 3.1 Fast reference-to-video**: the portraits keep faces consistent and the model speaks the dialogue with lip sync. Shots with nobody on screen use Veo 3.1 Fast text-to-video. 3. FFmpeg joins the shots into `drama.mp4`. | ~$0.15 per portrait, ~$1.20 per shot |
| `assemble` | Re-joins existing shots (e.g. after you regenerate one). | Free |

A 6-shot drama (~48 s) with 2 characters is about **$7.50** at fal.ai list
prices (Nov 2026). Check https://fal.ai/pricing before rendering.

## Setup

1. Create a key at https://fal.ai/dashboard/keys and add credit.
2. Put it in `config.toml` under `[app]`, or set the `FAL_KEY` environment variable:

   ```toml
   [app]
   fal_api_key = "your-key"
   ```

3. Pick your LLM in the WebUI (LLM Settings) as usual. Local Ollama works; a
   stronger model writes better scripts and returns valid JSON more reliably.

## Usage

```sh
python -m app.services.drama plan --project storage/dramas/last-train \
    --premise "A nurse on the last night train realises the stranger beside her is her missing brother" \
    --shots 6 --aspect 9:16

python -m app.services.drama estimate --project storage/dramas/last-train
python -m app.services.drama render   --project storage/dramas/last-train --yes --max-cost 10
```

The film is written to `storage/dramas/last-train/drama.mp4`.

- `render` without `--yes` only prints the estimate and spends nothing.
- `--max-cost` refuses to start if the estimate is higher.
- Finished portraits (`characters/*.jpg`) and shots (`shots/*.mp4`) are reused.
  An interrupted render resumes without paying again for finished parts.
- To redo one shot, edit it in `screenplay.json`, delete `shots/<id>.mp4`, and
  run `render --yes` again. To change a character's look, delete their portrait
  **and** every shot they appear in.
- `--bgm music.mp3 --bgm-volume 0.12` mixes quiet background music under the
  dialogue.

## Writing good screenplays

- Keep each shot to one clear action and at most ~20 words of dialogue; the
  model has 8 seconds.
- At most 2 characters per shot, at most 4 in the drama.
- `appearance` is repeated in every shot prompt. Be specific and keep one
  outfit: "34-year-old East Asian woman, shoulder-length black hair, navy nurse
  scrubs, small silver earrings".
- Fictional people only. Don't describe real or famous people; providers reject
  such prompts.

## Settings (`[app]` in config.toml)

| Key | Default |
|---|---|
| `fal_api_key` | (empty, or `FAL_KEY`) |
| `fal_drama_image_model` | `fal-ai/nano-banana-pro` |
| `fal_drama_reference_video_model` | `fal-ai/veo3.1/fast/reference-to-video` |
| `fal_drama_text_video_model` | `fal-ai/veo3.1/fast` |
| `fal_drama_resolution` | `1080p` |
| `fal_drama_shot_seconds` | `8` |
| `fal_drama_video_price_per_second` | `0.15` (estimates only) |
| `fal_drama_image_price` | `0.15` (estimates only) |
| `fal_drama_safety_tolerance` | `4` |

Switching models: any fal.ai endpoint with the same input fields
(`prompt`, `image_urls`, `aspect_ratio`, `duration`, `resolution`,
`generate_audio`) works, e.g. `fal-ai/veo3.1/reference-to-video` for the
higher-quality (and more expensive) Veo 3.1.

## Limits

- No subtitles yet. Veo speaks the lines, but the exact timing isn't known.
- Not in the WebUI yet; CLI only.
- Faces are consistent, not identical: reference images guide the model but
  small variations between shots are normal.
